# 案例形态学习与验证边界

用户指定三段行情作为开发案例；使用时序阶段特征直接学习其成功阶段，并加入同期失败商品作负例。正例要求此后第7—21日仍有至少15%收盘净涨幅潜力且14日净收益为正；未点名但上涨的商品不强行标负。

所有模型输入仅为当日可见的量价、品类及市场状态，名字、ID、事件身份、未来结果不进入特征。人工指定案例身份只用于训练标签，允许学习其形态，不能声称没有使用这些已知案例。

三类结果必须分开：

1. 按时间滚动的v3（output/rebound_stage）：训练只使用当时已成熟标签。
2. 事件留一（output/rebound_cases）：拿掉整段行情，用其余两段训练再回放被拿掉的一段。因为早期事件可能使用较晚事件训练，这是回溯机制检验，不是历史可执行验证。复杂度也用这三折AP选择，不能再称独立最终测试。
3. 已知案例拟合：在同一批开发案例上训练后回看，检查形态是否可分；高覆盖也不是泛化能力证明。

后续真正前瞻使用的模型，必须在所有训练标签成熟之后冻结。当前研究榜带有未获买入资格状态。卖出1%、买入0、零滑点；没有自动替换生产评分。

输出包括首次前10/前30时间、±7日最佳名次、首次入榜之后7/14日收益，完整同榜商品和各案例从前60日至后21日的特征路径。全量同榜记录用于检查误报，不能只展示已知赢家。
