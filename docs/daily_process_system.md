# 龙头过程评分系统 v1

本系统已实现数据更新、历史验证、逐日评分和评分留档，不执行交易。目前没有通过收益验证的买入系统。高证据分表示预设形态证据较齐，不表示大涨概率高或值得下单。

## 可复核的后台流程

1. 研究池排除指定低价武器类别，价格门槛30元；逐品类磨损分别研究。公开Firepulse悠悠日K按北京时间归日，仅用已完成日。保留原始响应缓存，增量合并最近60日；缓存不足时取1440日。
2. 至少300条历史有效记录；最近90自然日至少80条、20日至少18条；量能窗口33个有效观测跨越不超过45自然日。缺日不填零、不拼接SteamDT或BUFF价格。
3. 构建26个当时可知的特征。早期40个观测窗口截至21个观测日前；第二轮量价窗口约在21至7个观测日前；最近洗盘支撑和7个观测的量能分散度。窗口部分重叠，尚未证明它们是真实建仓和严格时序。
4. 六项先验形态证据最高100分，过热、单日量峰集中及跌破前低扣分。均匀放量综合相对量、量的变异系数与最大单日占比，避免把单日爆量等同持续吸筹。未满足的环节仍可能为0分，不能只读总分。
5. 分类模型学习大涨标签；收益回归模型作独立对照。各试7、15、31叶节点三组，参数只在校准段选择，不能用最后验证段最高值倒选参数。
6. 标签使用次日收盘作为买入代理，七日至三十日可退出区间按日收盘先达到净+20%还是净-10%记结果；必须有完整31日报价，最终退出日和买入日成交量须大于零。未触线按30日结果。手续费2.5%、买卖各0.5%滑点。七日最早退出是研究假设；没有真实盘口成交保证。
7. 训练要求标签在截至日前270日已成熟；校准信号在其后且在最近90日前成熟；最后90日只验证已具完整结果的信号。目前因此只有59个信号日。三个子时段是冻结模型的稳定性诊断，不是滚动重训。
8. 每天生成形态证据分、大涨模型相对排序、收益模型相对排序、各项理由、风险和数据日期。模型排序分位不是成功概率。保存每个数据日/算法版本第一次发布的快照，不回写第一次观察，以便前瞻检验。

## 核心边界

- 研究池广度、跌速、新低比例等市场状态是预设描述规则，不是已经通过最优化得出的情绪阀门；不会要求全池七日涨幅必须为正。
- 悠悠价格与全平台成交量严格分开。量价轨迹不证明真实会员身份、档位或成本；Whale仅辅助。
- 当前没有完整历史在售/求购与真实成交盘口，这些信息不得倒填。实时下单价格不能用昨日收盘替代。
- 分类模型初步提高了大涨标签识别率，但样本中高分组仍亏损；收益模型也未通过。人工证据分的大涨率不单调，因此不能声称“分数越高越值得买”。
- 样本按商品日计数，有时间重叠和品类相关性，平均收益不是账户组合收益。固定白名单、数据修订与幸存偏差仍待处理。七日分块重采样只处理一部分时间相关性。

## 每日入口

- `output/process_score_report.md`：完整结果与形态证据前20。
- `output/daily_process_scores.csv`：全池逐项参考表。
- `output/process_score_validation.json`：覆盖率、失败清单、两套模型、三段稳定性结果与限制。
- `output/history/`：第一次发布的逐日评分快照。
- GitHub Actions `Daily leader process scores`：北京时间每天10:15计划执行，GitHub排队可能延迟。每次保留原始缓存、模型和留出明细为30日artifact。

改变未来价格与成交量、核对历史26个特征及分数不变的检查见 `verify_process_causality.py`。它检验信息时间边界，不证明模型未来能赚钱。
